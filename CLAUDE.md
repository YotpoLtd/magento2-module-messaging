# magento2-module-messaging

## Purpose
The Yotpo SMS (SmsBump) extension for Magento 2 (`README.md:5`, `composer.json:3`). It is a Magento module, `Yotpo_SmsBump` (`registration.php:4`), that merchants install into their own store with Composer. It runs inside the merchant's Magento, not at Yotpo. It syncs customers and checkouts (abandoned carts) to the Yotpo API, adds an SMS-marketing consent checkbox to registration, account edit and checkout, restores abandoned carts from a link, and loads Yotpo's subscription-form, browse-abandonment and Klaviyo-capture scripts on the storefront. It depends on `yotpo/module-yotpo-core` (`Yotpo_Core`), which owns the API client, the store config and the admin section (`composer.json:12`, `etc/module.xml:4-6`). The GitHub owner is team Orbits (`CODEOWNERS`, commit `6120391`, ORB-1246). The repository is **public**.

## Stack
- Language: PHP. `composer.json` allows `~5.6.0|^7.0|^8.0`, but the code already needs 7.4 (typed properties); recent fixes target PHP 8.4 (commits `a0aaf58`, `bce6d6f`)
- Framework: Magento 2 (`magento/framework >=102.0.0`). README lists Magento 2.4.8 for module 4.3.3 (`README.md:19`)
- Runtime: the merchant's Magento install (web requests, cron, `bin/magento`)
- Package manager: Composer. The package is `yotpo/module-yotpo-messaging`, PSR-4 `Yotpo\SmsBump\` → repo root (`composer.json:15-22`). There is no `composer.lock` and no `vendor/`
- Key dependency: `yotpo/module-yotpo-core`, pinned to an exact version (`composer.json:12`). Most base classes come from it (`Yotpo\Core\Model\Config`, `Yotpo\Core\Model\Api\Request`, `Yotpo\Core\Model\AbstractJobs`)
- Frontend: RequireJS and Knockout checkout components (`view/frontend/requirejs-config.js`, `view/frontend/web/js/view/`)

## Directory Structure
Top-level only (run `ls` to verify if stale). Standard Magento module layout:
- `etc/`: module wiring: DI, events, plugins, cron, routes, admin config, DB schema, CSP
- `Model/`: config, sync processors (customers, checkout, subscription forms), abandoned cart, sessions, loggers
- `Plugin/`: interceptors on Magento core (quote, checkout, customer forms, login)
- `Observer/`: customer and address save, add-to-cart, admin config save
- `Controller/`: abandoned-cart restore, checkout consent save, admin "sync forms" button
- `Block/`, `ViewModel/`, `CustomerData/`, `Helper/`: storefront and admin rendering
- `Setup/Patch/Data/`: data patches that create the customer attributes
- `Api/`: the one service contract, `YotpoCustomersSyncRepositoryInterface`
- `view/`: layouts, templates, JS, LESS, the admin customer-form UI component
- `docs/`: maintenance notes and the harness docs

## Key Files
- `etc/di.xml`: loggers, the quote plugin, and preferences that replace Magento's checkbox classes and core's `Sync\Customers\Processor`
- `etc/frontend/di.xml`, `etc/webapi_rest/di.xml`, `etc/adminhtml/di.xml`: area-specific plugins
- `etc/db_schema.xml`: tables `yotpo_customers_sync` and `yotpo_abandoned_cart`
- `Model/Config.php`: config paths and API endpoints (`checkouts`, `customers`, `subscription-forms`)
- `Model/Sync/Customers/Processor.php`: customer sync, cron and real time
- `Model/Sync/Checkout/Processor.php` and `Model/Sync/Checkout/Data.php`: checkout sync on quote changes
- `Controller/AbandonedCart/LoadCart.php` and `Model/AbandonedCart/Data.php`: the abandoned-cart link
- `composer.json` and `etc/module.xml`: the module version (bumped together) and the core pin

## Don't Touch
- `etc/db_schema_whitelist.json`: generated by `bin/magento setup:db-declaration:generate-whitelist`. Change it only with `etc/db_schema.xml`
- `Setup/Patch/Data/*`: a data patch runs once per merchant install. Never edit an applied patch; add a new one
- `composer.json` version, `etc/module.xml` `setup_version`, the core pin: release decisions (`.claude/protected-files.json`)
- `LICENSE.txt`, `LICENSE_AFL.txt`: legal

## Quick Start
Commands come from `README.md:21-45`. They run in a Magento 2 root with this module installed, not in this repository.

- **Install:** `composer require yotpo/module-yotpo-messaging`, then `php bin/magento setup:upgrade`
- **Build:** `php bin/magento setup:di:compile` and `php bin/magento setup:static-content:deploy`
- **Test:** none. The repository has no tests (no `Test/` directory, no PHPUnit config)
- **Lint:** none configured. `docs/Maintenance.md` describes the PhpStorm "Php Inspections (EA Extended)" plugin; there is no command-line linter
- **CI:** none. There is no `.github/workflows/` (see [troubleshooting](docs/troubleshooting.md))
- **Agent checks:** `.agents/adlc/REPO_CHECKS.md`. `bash .agents/adlc/repo-validation.sh` is not configured yet (exits 2)

## Common Patterns
- Hook into Magento with a plugin or an observer declared in the right area's `etc/**/di.xml` or `events.xml`, never by editing core (`etc/frontend/di.xml:23-39`)
- API calls go through `Model/Sync/Main.php::sync()` with an `entityLog` key that picks the log file (`Model/Sync/Main.php:38-58`)
- Real-time syncs skip unchanged data by comparing JSON with the value kept in the session (`Model/Sync/Customers/Data.php:172-179`, `Model/Sync/Checkout/Data.php:202-216`)
- Per-store work wraps `emulateFrontendArea($storeId)` / `stopEnvironmentEmulation()` in `try`/`finally` (`Model/Sync/Customers/Processor.php:113-165`)
- A release bumps `composer.json` `version` and `etc/module.xml` `setup_version` to the same value, and often the core pin (commit `63af7fa`). Commits: `type(scope):message [ ORB-1234 ]`; branches `ORB-1234-short-desc`; PRs land as merge commits
